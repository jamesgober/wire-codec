# v1.1.0 - Hardening and Framing Extensions

`wire-codec` 1.1 is the first minor release on the 1.x line. It fixes every
correctness, security, and documentation finding of the October 2026
audit, the most serious being a remote panic on 32-bit targets (the few
items kept or deferred are listed under [Deferred](#deferred)), and
delivers the framing and codec work that the 1.0
roadmap listed for after the freeze: a varint length-prefixed framer,
checksummed frames, COBS, bit-packed structs, linear-time streaming, and
optional adapters for `bytes`, `tokio-util`, and `asynchronous-codec`.

The public API remains backward compatible. Everything new is additive,
and `cargo semver-checks` reports only minor-level changes against 1.0.0.
The minimum supported Rust version moves from 1.75 to 1.85; see
[MSRV](#msrv-175-to-185) below.

## Security and correctness fixes

- **Remote panic on 32-bit targets.** `LengthPrefixed::next_frame` computed
  `header_size + len` without overflow checks. On wasm32, armv7, thumbv7em,
  and i686, a `u32` prefix of `FF FF FF FF` overflowed `usize` and then
  panicked slicing the input. Every length taken from the wire is now
  converted with checked arithmetic, and an unaddressable length is
  reported as `FrameTooLarge`. A regression test runs on i686 in CI.
- **Padding bits leaked old data.** `BitWriter::align_to_byte` and
  `BitWriter::finish` moved the cursor without clearing the skipped bits, so
  a reused buffer sent stale bytes. Both now zero the padding, as the
  documentation always said.
- **Quadratic delimiter scans.** A peer dripping one long line a byte at a
  time forced a full rescan on every call (about 430 ms of CPU for a 64 KiB
  line). `StreamDecoder` and the new `Framer::next_frame_from` resume the
  search where it stopped; the same input now costs about 155 µs.
- **Frames the receiver could not read back.** `Delimited::write_frame`
  wrote payloads containing the delimiter, which the peer split into several
  frames. It now refuses them with `Error::DelimiterInPayload`, including the
  subtle case of a self-overlapping delimiter (`b"a"` before `b"aa"`), which
  the new fuzz harness surfaced during development.
- **Atomic operations.** Varint decoding used to leave the cursor part-way
  through a failed value, unlike every `ReadBuf` read. Now every read,
  write, encode, decode, and frame operation leaves its cursor at its
  original position on error. The crate's own writers (varint encoders,
  built-in framers, COBS, packed structs) also check room before writing,
  so they leave the buffer untouched; the crate docs list the two composite
  cases (tuples, `Checksummed` around an unbounded custom framer) where
  bytes can remain behind the restored cursor.
- **Bit-cursor capacity on 32-bit.** `len * 8` could overflow for slices of
  512 MiB or more; capacity is now saturated.

## New framing

- **`VarintPrefixed`.** The protobuf length-delimited stream format. It is
  bounded (8 MiB) and rejects overlong prefixes by default, both
  configurable.
- **`LengthPrefixed` extensions.** `LengthWidth::U24` (HTTP/2, TLS, MySQL)
  and `LengthWidth::U64`, plus `with_length_adjustment` for protocols whose
  length field counts the header or omits a trailer.
- **`Checksummed<F, C>`.** Wraps any framer and appends a checksum trailer,
  covering either the whole inner frame or the payload. CRC-16/CCITT-FALSE,
  CRC-32, and CRC-32C ship in the new `checksum` module; the `Checksum`
  trait accepts custom algorithms.
- **Bounded constructors.** `LengthPrefixed::bounded` (8 MiB) and
  `Delimited::bounded` (64 KiB) for input from untrusted peers. The 1.0
  constructors keep their unbounded behaviour; changing their defaults is
  reserved for 2.0.
- **Faster delimiter search.** A safe SWAR scan for the delimiter's first
  byte replaces the byte-by-byte slice compare, about 60x faster on a 1 KiB
  line. The optional `memchr` feature switches to the `memchr` crate's SIMD
  search.
- **`Framer::max_frame_len`.** A size bound that buffer-growing adapters use
  to reserve space once.

## New codecs

- **`packed_struct!`.** Declares a struct with a bit width per field and
  implements `Encode` and `Decode` for it. Widths are checked at compile
  time, values at encode time, and padding must be zero on decode, so each
  value has a single encoding. This makes the "packed struct encoding" of
  the crate description real.
- **`cobs`.** Allocation-free Consistent Overhead Byte Stuffing, including
  in-place decoding, for zero-delimited serial framing.
- **More varint.** `u16`, `usize`, and zigzag `i32` / `i64` helpers, and
  canonical decoders that reject overlong encodings with
  `Error::InvalidEncoding`.
- **More `Encode` / `Decode` impls.** `i8`, strict `bool`, byte arrays,
  tuples up to six elements, and the `Be<T>` / `Le<T>` / `Varint<T>`
  wrappers that make the byte order of each multi-byte field explicit.
- **Cursor helpers.** Signed, `u128`, and float reads and writes in both
  byte orders, `read_array`, `read_array_ref`, `peek_u8`, and `split_to`;
  `read_bool` / `read_signed_bits` and their writers on the bit cursors.

## Adapters

All optional and off by default:

- `bytes`: `codec::FrameCodec`, which runs any framer over a `BytesMut`
  buffer, splitting payloads off without copying. Works without `std`.
  `FrameCodec::reset` (and an automatic reset on decode errors) clears the
  resumable-scan state when the buffer is discarded or replaced.
- `tokio-util`: `Decoder` / `Encoder` for `FrameCodec`, so a framer drops
  straight into `tokio_util::codec::Framed`.
- `asynchronous-codec`: the same for futures-io based runtimes.

`Error` now implements `core::error::Error` on every target and, with
`std`, converts into `std::io::Error`.

## MSRV: 1.75 to 1.85

The MSRV moves to Rust 1.85 and the edition to 2024, matching the rest of
the net collection. The decision, weighed against REPS:

- REPS `VERSIONING` assigns MAJOR to breaking API, behaviour, and protocol
  changes. A toolchain requirement is none of those, and Rust's API
  evolution guidelines and Cargo's `rust-version` treat an MSRV raise as a
  minor change. It is therefore released as a MINOR version, never a PATCH.
- What 1.85 buys: `core::error::Error` for `no_std` users (1.81),
  edition 2024 for the crate itself, and current dev-dependencies
  (`proptest` 1.11, whose own `rust-version` is 1.85).
- What it costs: users on Rust 1.75 to 1.84. They should pin
  `wire-codec = "~1.0"`. Cargo skips 1.1 automatically only for projects
  that use MSRV-aware resolution (Cargo 1.84 or newer with
  `resolver = "3"` or `incompatible-rust-versions = "fallback"`); with an
  older Cargo, `wire-codec = "1"` resolves to 1.1 and fails to build.

The MSRV policy is now written down in the README and the crate docs.

The 1.0 CI matrix claimed to test 1.75 but almost certainly ran stable,
because `rust-toolchain.toml` takes precedence over `rustup default`. The
MSRV leg now sets `RUSTUP_TOOLCHAIN` and asserts the compiler version; it
caught one clippy difference on 1.85 on its first local run.

## Testing

- **Fuzzing.** `fuzz/` holds `cargo fuzz` targets for every decoder. The
  invariants (no panics, atomic errors, round-trip identity, canonical
  re-encoding, streaming equals batch decoding) live in a shared harness
  that also runs under proptest in `cargo test`, so they are exercised on
  Windows and 32-bit CI legs where libFuzzer is not available. Before
  release each target ran for 60 seconds under libFuzzer and AddressSanitizer
  (between 0.8 and 19 million executions per target) with no findings.
- **Coverage.** Line coverage rose from 82.6% to 99.2%
  (`cargo llvm-cov --all-features`). Every error path and every limit
  boundary (`max_payload`, `max_payload + 1`, exactly the header) has a test.
- **Docs as tests.** README and `docs/API.md` examples compile and run as
  doctests. Two 1.0 examples that did not compile are fixed.
- **CI.** New jobs: feature combinations, `no_std` and `wasm32` builds
  (including on 1.85), i686 Windows and Linux tests, a docs.rs-style nightly
  build, a fuzz smoke run, `cargo semver-checks`, and a weekly schedule.

Captured on the development machine (Windows 11, x86_64, single thread,
release profile, fat LTO), minimum of four runs. The COBS rows are ranges
across several sessions: their spread on this machine exceeded 10%, and
`cobs::decode` now validates the whole block before writing (a second pass
over the input). Decode inputs now pass
through `black_box`; the 1.0 decode figures were constant-folded and are not
comparable.

## Deferred

Recorded here so nothing is dropped silently:

- **`wire-codec-derive`.** A proc-macro derive needs a separate crate with
  `syn` / `quote`; `packed_struct!` covers bit-packed layouts without them.
- **SLIP framing, LSB-first bit order, a branchless varint fast path, an
  `alloc` ring buffer, and `zerocopy` interop.** Lower demand, or need API
  design beyond a minor release.
- **`criterion` benches.** The manual harness, now with `black_box`
  throughout, avoids a large dev-dependency tree.
- **Position context in errors and bounded defaults for `new`.** Both
  change existing behaviour or variants and are reserved for 2.0.
  `ReadBuf::position` reports the failing offset today, and the `bounded`
  constructors give the secure default.
- **`#![deny(warnings)]` stays.** The audit called it an anti-pattern, but
  REPS mandates it; CI also passes `-D warnings`.
- **`LengthPrefixed` header skip (`num_skip`) and length-field offset.**
  Protocols with bytes before the length field need an API for keeping or
  skipping the header; that design is left for a later minor release. A
  custom `Framer` covers them today.
- **A branchless varint fast path** for inputs with ten or more bytes
  available (audit WC-PERF-04, partially addressed: decode now runs on a
  local slice and commits once).
- **An end-to-end `tokio_util::codec::Framed` test.** The adapters are
  tested through their `Decoder` / `Encoder` traits directly, which is
  what `Framed` calls; a runtime-driven test would add `tokio` as a
  dev-dependency.
- **Canonical COBS.** `cobs::decode` accepts both encodings of a payload
  ending in a full 254-byte run, like the reference decoder. This is
  documented; callers that need a single encoding can re-encode and
  compare.

## Migration from 1.0.0

No code changes are required. A `cargo update -p wire-codec` on Rust 1.85
or newer is sufficient. Things to review:

- If you use `Delimited::write_frame` with payloads that may contain the
  delimiter, handle `Error::DelimiterInPayload` (1.0 silently wrote frames
  the peer would split).
- If you read untrusted input, switch `LengthPrefixed::new` and
  `Delimited::new` to their `bounded` counterparts or set
  `with_max_payload`, and drive streaming input through `StreamDecoder`.
- If you matched on the cursor position after a failed varint decode, it
  now stays at the start of the value.
- On Rust older than 1.85, pin `wire-codec = "~1.0"`.
